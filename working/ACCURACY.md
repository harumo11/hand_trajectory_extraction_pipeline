# 精度: 実測値と誤差要因

CLAUDE.md §7 の詳細版。**数値を主張するときは必ずここの実測条件とセットで扱うこと。**

計測環境: DJI Action2 実録画（2026-06-05）、被写体距離 約 0.5m。
独立基準は MediaPipe の 2D ランドマーク（HaWoR とは別系統の検出器）。

---

## 1. 実寸スケール — 誤差 5〜15%（Metric3D 依存）

HaWoR は masked DROID-SLAM の軌道スケールを Metric3D の単眼メトリック深度で決める。
world 出力は「近似メートル」であり、絶対実寸の保証はない。

**現行方針は α=1.0 固定**（HaWoR 内蔵スケールを信頼）。
実寸が要件化した場合の α 較正の選択肢:

1. 手の実寸測定（手長を実測して骨長比から α を出す）
2. 既知サイズのマーカーを撮影に写し込む
3. D405 の復活（面-面深度較正。[HISTORY.md](HISTORY.md) §4）

`world_trajectory.npz` の `alpha` フィールドと `export_trajectory.py --alpha` /
`--m3_report` がそのための受け皿。

**サニティチェックとして手長が使える**: `TrajectoryExporter.export` が
`[CHECK]` 行で手首〜中指 MCP 等の骨長から手長を出す。解剖学的な妥当範囲は 16〜20cm。
実測では 17.4〜18.4cm が出ている。

---

## 2. 画像面での位置整合 — 素の状態で 25〜55px

MediaPipe を独立基準にした実測。0.5m の距離で約 1.2〜2.6cm に相当する。

### 内訳
支配的なのは **HaWoR の並進回帰誤差**と **infiller の時間平滑化**。
較正パラメータでは詰められない（主点を ±18px 相当動かしても測定可能な改善は出ない）。

### 対策: 2D キーポイント並進リファイン（実装済み）
`handtraj/refine.py` / `run_pipeline --refine`。
ホールドアウト評価（関門④b）で **55.0px → 16.1px** に改善。
fit 側 15.8px とほぼ同値なので過学習ではない。

### 残る 16px の正体 — 軌道誤差ではない
MANO の関節中心と MediaPipe ランドマークの**定義差**が支配的:

| 部位 | 定義差 |
|---|---|
| 手首 | 18px |
| MCP | 25px |
| PIP / DIP | 12px |

つまり 16px は「両者の関節定義がそもそも違う」ことによる床であり、
これ以上 2D 残差を下げても軌道が良くなるわけではない。

## 3. 理想ピンホール化（rectify）について — 【訂正済み】

`run_pipeline.py` は既定で歪み補正 ＋ 主点センタリングを行い、HaWoR の内部仮定
（fx=fy・主点=中央・歪み 0）と入力を一致させる（`--no_rectify` で無効化）。

**ただし、この補正によるオーバーレイ整合の改善は実測では確認されていない。**
主点が 26px ずれている環境で、補正前後の投影差は 1.6〜5.6px にとどまった。
系統誤差は §2 のとおり HaWoR の並進回帰自体が支配的で、較正パラメータでは動かない。

rectify は「衛生措置」（入力とモデル仮定を揃えておく）として残しているのであって、
精度改善策ではない。**精度改善を主張するときは必ず定量比較とセットにすること。**

## 4. リファインの限界と副作用

### 奥行き成分は部分的にしか復元できない
2D 観測の情報限界による原理的な制約。selftest（関門④a）の実測:

- 面内（画像平面方向）: **96%** 復元
- 奥行き方向: **65%** 復元

人工オフセット ±2cm のケースで面内 95.7% 復元、残差 32.5→3.4px。

### 副作用の検証（関門④c）
- **手長は完全不変** — Δt は手ごとの剛体シフトなので形状に触れない
- **ジャーク +3.5%** — 平滑化項の重み `σ_vel=0.003` はこの値を許容範囲に収めて選んだ
  （`TranslationRefiner.solve` の既定は 0.01 だが、`refine_take` は 0.003 を渡す）

## 5. 未対策の誤差

- **位置・回転ドリフト** — 未補正（HaWoR 任せ）。長尺動画の絶対精度は静止区間で要実測
- **検出失敗・画面外** — `valid=False` になり、該当関節は NaN
- **fps** — HaWoR は 30fps 前提。30fps 以外の入力を ffmpeg で再サンプルすると
  フレーム番号の 1:1 対応が崩れうる
